# i18n: flutter_localizations + intl + ARB

Target: Flutter stable / Dart 3.x, `intl` 0.20.x. Use the official `gen-l10n` + ARB workflow: ARB is
the ecosystem interchange format, so switching generators later is a scripted import. The behaviour
below was verified against the SDK's own `gen-l10n`.

## Setup

```yaml
# pubspec.yaml
dependencies:
  flutter_localizations:
    sdk: flutter
  intl: any   # let Flutter pin the version it ships with

flutter:
  generate: true   # MANDATORY: without it nothing is generated
```

```yaml
# l10n.yaml
arb-dir: lib/l10n
template-arb-file: app_en.arb
output-localization-file: app_localizations.dart
output-class: AppLocalizations
nullable-getter: false
untranslated-messages-file: build/untranslated.json
```

The complete key set is `arb-dir`, `output-dir`, `template-arb-file`, `output-localization-file`,
`output-class`, `untranslated-messages-file`, `header`, `header-file`, `use-deferred-loading`,
`preferred-supported-locales`, `required-resource-attributes`, `nullable-getter`, `format`,
`use-escaping`, `suppress-warnings`, `relax-syntax`, `use-named-parameters`.

- **`synthetic-package` has been removed.** Setting it to `true` fails the tool ("this feature has been
  removed"); `false` prints a deprecation warning, so delete the key. The old
  `package:flutter_gen/gen_l10n/...` import is gone: generated files land in `arb-dir` (`lib/l10n`).
- `nullable-getter` defaults to `true`, so `AppLocalizations.of(context)` is nullable and every call
  site needs `!`. Set `false` and the generated getter checks for you: a compile error instead.
- `required-resource-attributes: true` forces a description on every message. `use-escaping: true` makes
  single-quoted text literal, which is how a literal `{` ships; `relax-syntax` allows an unmatched `{`.

```bash
flutter gen-l10n     # explicit regeneration, and what CI should run
flutter pub get      # also regenerates when "generate: true" is set
```

Generation also runs during `flutter run` / `flutter build`, but only with both `generate: true` and
an `l10n.yaml`; without `l10n.yaml` it is skipped, which looks like "my new key is missing".

## Wiring the app

```dart
MaterialApp(
  onGenerateTitle: (context) => AppLocalizations.of(context).appTitle,
  localizationsDelegates: const [
    AppLocalizations.delegate,
    ...GlobalMaterialLocalizations.delegates, // Material + Cupertino + Widgets
  ],
  supportedLocales: AppLocalizations.supportedLocales,
)
```

- `AppLocalizations.of(context)` in `build()` is the normal access path; it resolves through the
  `Localizations` widget that `MaterialApp` installs. Use `onGenerateTitle`, not `title:`: `title` has
  no `context` to resolve a translation from.
- The classic "Null check operator used on a null value" comes from calling it with a `context` above
  or outside `MaterialApp` (in `MaterialApp.builder`, before the app starts, in an overlay route
  outside the localizations subtree). Move the call below `MaterialApp`, and set `nullable-getter:
  false` so the mistake is a compile error.

## ARB: messages, metadata, placeholders

```json
{
  "@@locale": "en",
  "appTitle": "Notes",
  "itemCount": "{count} items in {folder}",
  "@itemCount": {
    "description": "Number of items in a folder",
    "placeholders": {
      "count": { "type": "int", "example": "3" },
      "folder": { "type": "String", "example": "Work" }
    }
  }
}
```

- The template file (`app_en.arb`) is the source of truth; `@@locale` declares the file's locale.
  Declare every placeholder in `@message.placeholders` with its `type` (`String`, `int`, `double`,
  `num`, `DateTime`): the type decides the generated Dart signature and the formatting applied first.
- Never concatenate fragments: `l10n.hello + ', ' + name` cannot be reordered or inflected, and breaks
  wherever the name comes first.

```dart
Text('Hello, ' + name);                          // WRONG: concatenation
Text('You have ' + count.toString() + ' items'); // WRONG: no plural form
Text(l10n.itemCount(count, folderName));         // RIGHT
```

## Plurals

```json
"itemsSelected": "{count, plural, =0{No items selected} =1{1 item selected} other{{count} items selected}}",
"@itemsSelected": { "description": "Selection counter", "placeholders": { "count": { "type": "int" } } }
```

- Always write `=0`, `=1` and `other`. A missing `other` fails generation with exit 1:
  `ICU Syntax Error: Plural expressions must have an "other" case.`
- `one`/`other` alone is wrong outside English-like languages: plural categories are per-language
  (Arabic zero/one/two/few/many/other, Russian one/few/many/other) and `intl` picks the category for a
  number. Special-case what you must; let `other` cover the rest.
- **Do not use the ICU `#` shorthand.** Flutter's generator has no `#` handling, so `other{# items}`
  emits a literal `#`. Repeat the placeholder instead: `other{{count} items}`.

## Select (gender, roles, variants)

```json
"pronoun": "{gender, select, female{She} male{He} other{They}} shared the note",
"@pronoun": { "description": "Pronoun for the actor", "placeholders": { "gender": { "type": "String" } } }
```

- The value is matched **case-sensitively** against the ARB cases: `"Male"` falls through to `other`.
  Normalize to lowercase at the boundary and keep wire values lowercase. `other` is mandatory here too.
- Never derive a pronoun from a name or an avatar: store the preference and default to `other`.

## Numbers, dates and currencies in the active locale

```dart
// WRONG: no locale, so intl uses its hardcoded systemLocale of en_US
final amount = NumberFormat.currency(symbol: r'$').format(total);
final when = DateFormat.yMMMd().format(createdAt);
// RIGHT: bind the formatter to the locale the app is actually showing
final locale = Localizations.localeOf(context).toLanguageTag();
final amount = NumberFormat.simpleCurrency(locale: locale).format(total);
final when = DateFormat.yMMMd(locale).format(createdAt.toLocal());
```

- `Intl.systemLocale` is hardcoded to `'en_US'` in `package:intl` and Flutter never sets
  `Intl.defaultLocale`, so a formatter built without an explicit locale formats as US English on every
  device: wrong decimal separator, wrong date order, wrong currency placement.
- Read `Localizations.localeOf(context)`, not `Platform.localeName`: the widget value follows the
  language the user picked inside the app.
- You do **not** need `initializeDateFormatting()` in Flutter: `GlobalMaterialLocalizations.load()`
  loads the intl date symbols. Without those delegates, dates work in English and throw
  `LocaleDataException` elsewhere, which is normally misdiagnosed as missing locale data.
- Format for display only: a persisted formatted string is locale-dependent and cannot be sorted or
  parsed back. Set `Intl.defaultLocale` from the same resolved locale, or not at all.

## RTL

- `GlobalWidgetsLocalizations` sets `Directionality` from the locale, so Arabic, Hebrew, Farsi and Urdu
  lay out right-to-left with no extra work. Test with `Locale('ar')`.
- Use direction-aware geometry everywhere: `EdgeInsetsDirectional.only(start:, end:)`,
  `AlignmentDirectional.centerStart`, `PositionedDirectional`, `BorderRadiusDirectional`. A literal
  `EdgeInsets.only(left: 16)` is a bug in half the world. Mirror what should mirror: chevrons flip, a
  clock face, checkmark, logo and media controls do not. Never reverse digits in RTL text.

## Semantics, store metadata, and everything that is not a `Text`

A localized UI with English accessibility labels is not localized.

- `Semantics(label: l10n.playButtonLabel, button: true, child: ...)` for icon-only controls, plus
  `tooltip:` and `semanticLabel:`: all come from ARB like any other string.
- Store metadata is localized too: title, subtitle, short and full description, release notes and
  screenshots per locale. A localized UI with an English store listing loses most of the work.
- Notification text, permission rationale and deep-link landing copy are user-facing, so they come from
  ARB too. Scheduled notifications keep the string they were created with: rebuild on locale change.

## Catching hardcoded user-facing strings in CI

There is **no official analyzer rule** for this: `flutter_lints` has nothing string-related, and
`hardcoded_strings_lint` is an analyzer plugin, which `flutter analyze` does not run on Flutter 3.47
(that route needs `dart analyze`). Do not assume a lint protects you. A grep gate costs nothing:

```bash
git grep -nE "(Text|SelectableText|tooltip|semanticLabel|label|hintText|helperText|title)\s*:\s*['\"]|Text\(\s*['\"]" \
  -- 'lib/**/*.dart' ':!lib/l10n/**' ':!**/*.g.dart' ':!**/*.freezed.dart'
```

Look for, in order of how often they are missed: `Text('...')`, `label:`/`hintText:` on form fields,
`tooltip:`, `semanticLabel:`, `SnackBar(content: Text(...))`, dialog titles, `AppBar(title:)`,
empty-state copy and error strings.

Escape hatches must be explicit and short:

```dart
Text('v1.2.3', semanticsLabel: l10n.versionLabel), // numbers, units, symbols
// i18n-exempt: brand name, never translated
const Text('Acme');
```

Every exemption is a string a translator cannot see; symbols and numbers belong in ARB with a
placeholder anyway. Translation completeness is a separate gate, and `gen-l10n` never fails on it: it
exits 0 and prints a count. Use the JSON report instead.

```bash
flutter gen-l10n
[ "$(tr -d '[:space:]' < build/untranslated.json)" = "{}" ] || { echo "untranslated messages"; exit 1; }
```

Also fail when a key exists in a translation but not in the template: keys drift silently.

## Common mistakes

| Mistake | Symptom |
|---|---|
| `Text('Hello')` | English text in every language, and no error ever |
| Concatenating translated fragments | Wrong word order and grammar in inflected languages |
| Plural with only `one`/`other` | Wrong form for Arabic, Russian, Polish and others |
| Missing `other` case | Build fails: `ICU Syntax Error: Plural expressions must have an "other" case.` |
| `DateFormat`/`NumberFormat` without the active locale | US English dates and currency on every device (`Intl.systemLocale` is `en_US`) |
| `Intl.defaultLocale` never set | Formatters built in services ignore the language the user picked |
| ARB key added to a translation but not the template | Key never generated, or silently dropped on regeneration |
